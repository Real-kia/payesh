# Package 04 handoff — fleet identity and web access checkpoint

Status: implementation checkpoint expanded; package 04 is not yet fully
accepted. Ubuntu 22 core/kernel evidence and a real Ubuntu-hub to Debian-node
TLS bootstrap plus monitoring-ingestion run are current. Live certificate
renewal, remote action delivery, and SSH-driven installation remain.

## Implemented

- `internal/auth` provides one-time owner setup, PBKDF2-HMAC-SHA256 password
  records, opaque hashed session handles, SameSite/HttpOnly cookies (Secure by
  default, with an explicit local loopback HTTP mode), CSRF validation for
  browser mutations, expiry, logout, and bounded/expiring login throttling.
  Owner, session and throttle records are persisted in SQLite with bounded,
  fail-closed restore behavior.
- `internal/fleet` exposes `/api/v1/setup` and `/api/v1/session` and wraps the
  existing bounded monitoring reads with session authentication. The server
  keeps package-03 bearer-token mode unless `--bootstrap-secret` (or
  `PAYESH_BOOTSTRAP_SECRET`) enables browser sessions. Trusted reverse-proxy
  CIDRs can be configured with `--trusted-proxy-cidrs` or
  `PAYESH_TRUSTED_PROXY_CIDRS`; forwarded addresses are ignored otherwise.
- `internal/transport` provides an enrollment CA, ten-minute single-use pairing
  tokens whose digest and consumption state are CA-owned, one certificate and
  pending token per server, 90-day client certificates,
  revocation/fingerprint checks that terminate live revoked channels,
  one-live-connection-per-node enforcement,
  compatible typed hello validation, durable batch ingestion with contiguous
  sequence acknowledgements, heartbeat refresh, and a bounded typed job queue.
  Its CA key/certificate, pending token digests, certificate ownership and
  revocations have a restricted SQLite persistence adapter.
- `internal/install` provides side-effect-free role/platform/init/artifact
  preflight checks against the pinned Linux release matrix and rejects service
  roles without systemd or OpenRC; node preflight never includes server or web
  assets. `cmd/payesh-install` exposes that decision as an inspectable CLI
  (`--json` is available for a future direct or hub-assisted installer) and
  exits non-zero for unsupported targets without making host changes. The
  report also identifies kernel, package manager, cgroup mode, privilege, and
  `ip`/`tc`/`nft` availability, keeping optional-control gaps as explicit
  warnings rather than blocking monitoring-only installs.
- `internal/transport/spool.go` provides a bounded 32 MiB (configurable below
  that ceiling) crash-safe offline queue. It validates single-epoch batches,
  atomically rewrites on append/acknowledgement, reports explicit
  `spool-eviction` coverage gaps, rejects corruption/oversized records, and
  preserves restrictive file permissions across restart.
- `internal/transport/frame.go` provides bounded typed frame encoding/decoding
  with partial-I/O handling, strict protocol/type validation, and capped
  exponential reconnect backoff with injectable jitter. It is transport-neutral
  and ready for the authenticated TLS/WebSocket adapter.

## Restart-safe browser authentication follow-up (2026-09-11)

Owner password records, session digests/CSRF metadata, and bounded login
throttle state now persist atomically in the existing restricted SQLite store.
Reopening the store cannot reopen one-time setup, and an unexpired session
survives server restart. Persistence is bounded to 256 sessions and 4,096
throttle keys; invalid or oversized state fails startup closed. The setup
secret and cleartext passwords/session tokens are never stored. Coverage is in
`TestOwnerAndSessionSurviveStoreReopen` plus the existing auth tests.

The enrollment authority now also has a restricted SQLite persistence adapter.
Its CA key/certificate, pending token digests, issued-certificate ownership,
and revocation fingerprints survive restart; pairing-token cleartext and node
private keys are not retained. Authority state is bounded and corrupt or
oversized state fails startup closed. The database-reopen test covers a
pending enrollment, a usable issued identity, a revoked identity, and stable
CA trust.

The shared job foundation is now persistent in SQLite and bounded at 10,000
rows. Creation deduplicates by kind/server/idempotency key while rejecting a
key reused for different input; worker transitions and cancellation use
revision compare-and-swap. Cancellation results are themselves durable and
idempotent across restart. Authenticated `GET /api/v1/jobs/{jobId}` and
`POST /api/v1/jobs/{jobId}` routes expose read and cancel behavior.
`internal/fleet/enrollment.go` now adds the authenticated
`POST /api/v1/servers/{serverId}/enrollment` producer: it validates the
CA-owned pairing-token digest without persisting cleartext, creates a bounded
idempotent `enrollment` job, and returns the durable queued job. Replays return
the original job and conflicting idempotency input fails closed.
`transport.Hub.ConsumeEnrollmentJob` now claims the job with a durable CAS,
accepts the pairing token only from the node at claim time, invokes the
single-use CA consumer, and transitions the job to succeeded/failed. The
token, generated private key, and certificate payload are never persisted in
the jobs table. The CA also now
exposes a bootstrap-only `ConsumeEnrollmentToken` seam and the hub validates
durable server ownership before consuming it, so a node can present its
short-lived token without the hub storing cleartext. `Renew` rotates an
enrolled certificate, persists new ownership, and revokes the predecessor.

## Live transport follow-up

An opt-in TLS 1.3 RFC 6455 listener now connects the production server to
`transport.Hub`, while transport mode in `payesh-agent` loads the enrolled
identity and hub trust anchor, collects into the bounded spool, reconnects,
replays, sends heartbeats, and removes samples only after the hub's cumulative
durable acknowledgement. Spool-eviction gaps are themselves persisted ahead of
retained samples and survive restart. Plain stdout mode remains the default.

The listener also exposes a server-authenticated bootstrap route without a
client certificate; `/node/v1` still requires and authoritatively verifies a
node certificate. Bootstrap consumes the durable job/single-use token and
atomically saves the identity. Renewal revokes the predecessor and persists
the replacement before reconnect. Durable actions use expiring SQLite leases;
results are bound to the lease owned by the exact authenticated connection.
The agent advertises actions only when `PAYESH_PRIVD_SOCKET` configures the
typed local helper.

`internal/transport/multi_server_integration_test.go` adds a disposable
multi-node acceptance path. With `PAYESH_LIVE_TRANSPORT_ACCEPTANCE=1`, it
allocates an ephemeral IPv4 listener, creates a temporary TLS 1.3 hub
certificate, bootstraps two independent nodes with separate durable jobs and
single-use tokens, reconnects both with their issued client certificates, and
verifies that each node's sample is durably ingested under the correct server
identity. The default test suite skips this listener-owning test so restricted
CI sandboxes and shared hosts are never modified accidentally. The test does
not constitute production multi-host evidence; it is the local two-node
transport gate that should pass before a disposable-server run.

`payesh-install --install --artifact-dir ...` installs role-specific already
verified artifacts and systemd/OpenRC services. Repeated/partial runs preserve
identity and resume; web assets retain the prior complete bundle until the new
bundle activates.

`internal/install/ssh.go` now supplies the hub-assisted boundary. It requires a
caller-provided artifact verifier before any installer/artifact transfer and
rejects relative, dash-prefixed, symlinked, special, or non-clean local paths
(`web-assets` must be a real directory). It verifies
exact known-host entries or an explicitly confirmed/expected fingerprint,
rejects changed keys, transfers only locally verified role artifacts through a
transient staging directory, supports OpenSSH password and encrypted-key
authentication (the latter through a short-lived `ssh-agent`/askpass pair),
and clears credential buffers after the job. Remote installation is delegated
to the same `payesh-install` executable; enrollment and real measurement
arrival are required callbacks before the result reaches `complete`. The
transport interface is injectable for job tests and never includes command
output or credentials in `SSHInstallResult` errors.

The browser fleet API now binds this boundary to durable jobs. `POST
/api/v1/installations` and `POST /api/v1/servers/{serverId}/install` require the
existing session/CSRF boundary and return an `install-ssh` job. The durable row
contains only target metadata and an idempotency hash that excludes credentials;
SSH passwords, keys, and passphrases are held in a bounded process-memory
handoff and cleared after execution. A process restart therefore cannot
resurrect credentials; the next worker pass records a retryable
`credentials_unavailable` failure. `POST /api/v1/updates` similarly delegates
owner plans to the restart-safe updater scheduler.

The owner-facing `POST /api/v1/servers/{serverId}/enrollment-token` seam now
issues a ten-minute single-use pairing token after the existing authenticated
session and CSRF checks. It requires an idempotency key, returns the token and
expiry only to the owner, replays the same response from a bounded process
memory cache during the token lifetime, and rejects a second active token for
the server. Cleartext tokens are not written to SQLite, jobs, or logs; after a
process restart the CA retains only the digest and the operator must wait for
expiry before requesting a replacement. OpenAPI and contract checks cover the
new route and response shape.

The server starts a bounded installation worker in browser mode. The default
binary does not invent artifact paths, enrollment callbacks, or signing trust;
without an explicitly configured `InstallService.Executor` a new installation
request returns `503 install_executor_unavailable`, while any pre-existing
durable row settles as `executor_unavailable` during recovery.

## Explicit omissions

Signed release fetching/signature integration is still separate: callers must
provide already verified installer and role artifacts plus a verifier callback.
The SSH transport has not been exercised against a disposable Linux target;
password, encrypted-key, changed-key, custom-port, sudo, interrupted-upload,
and full-disk acceptance remain unrun. Production enrollment must provide the
authenticated `Enroll` and `VerifyMeasurements` callbacks; the installer
fails closed when either is absent. Live TLS bootstrap and monitoring ingestion
passed on 2026-09-12 between a temporary Ubuntu 22.04 amd64 hub and a temporary
foreground Debian 12 arm64 node. The node consumed a durable single-use
enrollment job, saved its issued identity, sent sequence zero, and the hub
queried the durable sample under the expected server ID. Cleanup removed both
temporary deployments. Live renewal and action delivery remain unrun; the
standard server runner still exercises only the standalone core/API and kernel
profiles.

The first attempt exposed an acceptance-deployment hazard: a slow SCP/SFTP
session can leave a partially written executable that fails with `ETXTBSY` or
an archive that fails with unexpected EOF. Real-host automation must upload to
a `.part` name, wait for transfer completion, verify the expected SHA-256, and
only then atomically rename/unpack and execute it. The successful run followed
that boundary.

On 2026-09-12 the supplied Ubuntu 22.04 amd64 host rebooted on request and
accepted SSH again after 13 seconds; `systemd` reported `running` after
recovery. The `core` profile then passed collector identity/epoch, SQLite
ingest/query, and authenticated local API checks. The focused `nft` profile
passed guarded apply/snapshot/remove with cleanup. The focused `bandwidth`
profile passed the tc backend and the corrected shaped-veth throughput probe
passed. The network profile passed veth/namespace, bridge, isolated NAT, and
TUN checks. Podman 3.4.4 was installed for runtime coverage; a disposable
Alpine bridge container passed outbound connectivity. The only network
capability still reported unsupported on that host is offload inspection on a
disposable veth. No Payesh unit was installed on that host, so this remains
reboot/runner evidence, not persistent Payesh service-install acceptance.

The server's default browser listener is loopback HTTP and therefore uses the
local cookie mode. Non-loopback browser listeners are rejected unless
`--secure-browser-cookies` is set for deployment behind HTTPS.

## Verification

Passed: `GOCACHE=/private/tmp/payesh-go-cache go test ./...`,
`GOCACHE=/private/tmp/payesh-go-cache go test -race ./...`, `go vet ./...`,
`GOCACHE=/private/tmp/payesh-go-cache make lint`, `make contract-check`,
`make build`, `make build-matrix`, and `make web-check`. Tests cover one-time
setup, bounded/expiring throttling, trusted-proxy client keys, CSRF, enrollment
expiry/reuse/revocation (including copied-token replay), revoked-channel close,
duplicate and post-close connections, compatible protocol ranges, sequence-zero
and contiguous durable acknowledgements, revision/deadline-safe jobs, both
browser cookie modes, database-reopen auth/CA continuity, bootstrap-token
consumption/replay rejection, certificate rotation/revocation, and the pinned
release/architecture/init preflight. An opt-in Linux preflight run on the
supplied Ubuntu 20.04 host correctly reported `supported=false` with the
matrix reason, so installation fails closed; transport, installer, and
resource measurements still require a supported disposable Linux image. The
preflight CLI is covered by the package build and can run against a mounted
target root before credentials or artifacts are handled.

Remote evidence (2026-09-12, Ubuntu 22.04 amd64, root, disposable runner):
a fresh core rerun passed collector identity/epoch, SQLite ingest/query, and
authenticated API startup against the populated database. The earlier
one-off SIGSEGV did not reproduce across 20 local launches or the fresh remote
run; later testing found that slow transfers had left executables incomplete
or still open for writing. Acceptance artifacts must therefore be transferred
to a staging name, checksum-verified, and atomically published before use. The focused
`nft` profile returned `port_traffic_nft=PASS`; the focused `bandwidth`
profile returned `bandwidth_tc=PASS` and
`bandwidth_throughput=UNSUPPORTED reason=traffic-path-or-capability-unavailable`.
The host rebooted and was reachable again in 13 seconds with
`systemd=running`. A separate uniquely named Payesh systemd unit using a
persistent `/var/lib/payesh-live-acceptance` test path started, restarted,
survived the same authorized reboot, and passed `/healthz`; its unit, timer,
and state were removed. The runner removed each exact remote temporary
directory.

## Next inputs

authenticated node bootstrap/WebSocket framing and bind it to
`InstallOverSSH` progress/cancellation. Preserve
`transport.Hub.Open`/`ReceiveBatch` semantics and call acknowledgements only
after `Store.IngestNodeBatch` returns durable acceptance.
