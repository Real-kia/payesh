# Package 02 handoff — UI/UX and dashboard

Date: 2026-09-09  
Status: Checkpoint A preview implemented; production API integration remains intentionally deferred to packages 03/04.

## Files and baseline

The package builds on the package-01 Svelte/Vite shell. The UI surface is in
`web/src/App.svelte`, with the uPlot chart in `web/src/ChartPreview.svelte`,
the compact sparkline in `web/src/Sparkline.svelte`, and the explicit preview
boundary in `web/src/preview/fixtures.ts`. `web/build-check.mjs` now checks the
preview contract and required state coverage. `web/src/app.d.ts` includes the
Vite environment types.

## Implemented preview behavior

- Responsive desktop/mobile shell with complete horizontal mobile navigation;
  Overview, Alerts, Extras, and Settings remain reachable at narrow widths.
- System light/dark preference on first visit, explicit theme persistence, and
  reduced-motion handling for the loading indicator.
- Preview-only dynamic fixture adapter. Normal production builds do not load or
  bundle fixture values; failed/empty/loading/error states are explicit.
- Fleet overview sorted by attention first, with healthy, stale, pending,
  unreachable, installing, failed, disabled, and unsupported states rendered
  with text and status indicators.
- Server detail tabs for metrics, traffic, and bounded logs. Traffic keeps
  decimal-string byte counters at the adapter boundary and displays timezone,
  direction, allowance, and continuity metadata. Logs show source and cursor.
- uPlot resource history with 15-minute, one-hour, and 24-hour range selection,
  selected-server CPU/memory data, readable elapsed-time axes, units, min/max
  context, gap summary, and keyboard/screen reader labeling. Histories remain
  behind the dynamic preview adapter and unavailable servers never receive a
  fabricated chart.
- Detail tabs are capability-gated; unsupported metrics, traffic, and logs show
  an explicit reason instead of an empty or fabricated panel. Long server names
  wrap safely at mobile widths and status colors meet the small-text contrast
  target in both themes.
- Three-step onboarding: workspace/access validation (bootstrap secret and
  owner password), retention/notification defaults, and optional single-use
  pairing-token enrollment with a skip path. Secrets/tokens are not persisted.
- Local UI state preserves selected page, server, tab, and theme across refresh;
  browser history restores the same state on back/forward navigation.

## Consumed interfaces and future integration

The preview adapter mirrors the approved `Server`, metrics, traffic, and log
metadata contracts but does not call `/api/v1`. Package 03 must provide local
metrics/log storage and bounded responses; package 04 must provide authenticated
session/enrollment and durable job state. Replace only the adapter/import path,
retain distinct stale/missing states, reconcile jobs after refresh, and use
bounded/virtualized render paths before production acceptance.

## Verification

Executed from `web/`:

```text
npm run check
npm run build
```

Both complete successfully. `svelte-check` reports zero errors and zero
warnings. The latest Vite build is 109.18 KiB JavaScript plus 21.37 KiB CSS
(43.99 KiB plus 4.50 KiB gzip), below the 300 KiB initial compressed target.
The production bundle does not contain fixture names; the preview adapter is a
development/explicit-preview dynamic chunk. A browser surface is unavailable in
this environment, so screenshots at 375/768/1440px, 200% zoom, and manual
screen-reader checks remain unrun.

## Security, scope, and omissions

No credentials, tokens, API calls, polling, or live subscriptions were added.
Onboarding inputs are local preview values and are deliberately never placed in
local storage or URLs. The UI is not evidence of real monitoring, access
control, enrollment, alert delivery, or production performance; those belong to
later package checkpoints.
