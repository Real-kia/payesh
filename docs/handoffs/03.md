# Package 03 handoff — local monitoring checkpoint

Status: Checkpoint A implemented; core Linux collector/ingest acceptance is now
evidenced on the disposable Ubuntu server, but the complete M2 gate and package
acceptance are still pending.

## Baseline and files

- Shared contracts remain under `internal/contracts`; package 03 adds the typed
  `TrafficPeriod` allowance/usage record with decimal-string byte fields.
- SQLite-free collection is in `internal/collector/`; persistence/API and a
  source-compatible wrapper are in `internal/monitoring/`.
- Executables are `cmd/payesh-agent`, `cmd/payesh-server`, and `cmd/payesh`.
- Init definitions are `deploy/systemd/payesh-{agent,server}.service` and
  `deploy/openrc/payesh-{agent,server}`.

## Implemented behavior

- Linux proc/syscall collectors read CPU utilization/iowait/steal, memory and
  swap, load, uptime, disk capacity/inodes, disk I/O, and per-interface network
  bytes/packets/errors/drops. First samples, counter resets, overflow, missing
  files, virtual interfaces, and unavailable values remain explicit; billing
  estimates never sum loopback/virtual interfaces by default.
- Node samples omit `received_at`; `Store.IngestNodeBatch` stamps the hub/store
  receipt time and preserves source-clock-ahead uncertainty.
- `payesh-agent` imports only `internal/collector` and `internal/contracts`;
  `go list -deps ./cmd/payesh-agent` contains no SQLite or monitoring-store
  dependency. The server/CLI retain the SQLite-backed monitoring package.
- SQLite uses WAL, foreign keys, restrictive database permissions, durable
  deduplication on `(server_id, collector_epoch, sequence)`, bounded cursors,
  durable coverage gaps, metric rollups, traffic periods, log sources/entries,
  and bounded retention/storage-pressure checks.
- Omitted collector-epoch flags generate a fresh random epoch for each agent
  start. Ingestion materializes affected persisted minute/hour rollups (plus
  neighboring buckets), carries cross-bucket counter intervals into the bucket
  containing the ending sample, and carries adjacent gauge intervals across
  UTC bucket edges without manufacturing buckets across long outages.
- Rollups are UTC minute/hour buckets over samples that exist. Gauges carry
  count/duration/min/max/time-weighted mean; counters carry only valid deltas
  and become uncertain across resets or sequence gaps. No empty samples are
  manufactured. Persisted rollups back minute/hour API and CLI queries.
- Configured file logs reject relative paths, symlinks, and non-regular files;
  they cap entries/bytes/line size, replace invalid UTF-8, group readable
  continuations, redact obvious credential fields, and expose file identity/
  offset cursors. A bounded live-tail helper and protected local NDJSON route
  handle registered sources only. A fixed-argument `journalctl --output=json`
  snapshot adapter is available when systemd journald exists.
- File cursors use stable device/inode identity, so appends do not replay old
  entries; live-tail responses are allowed to wait through their five-minute
  maximum without the server write deadline expiring first.
- Unterminated file writes remain pending until a newline arrives, so a live
  tail never advances a resumable cursor through a partial event. Live-tail
  source authorization uses an exact database lookup and is not limited to
  the first 200 registered sources.
- A late sample also invalidates/rebuilds the bucket containing its later
  endpoint sample. Durable raw ingestion acknowledgements are independent of
  derived rollup writes: affected targets enter a durable rebuild queue when
  storage pressure or a transient database error pauses materialization, and
  reads retry queued work after headroom returns.
- Current and existing traffic-period rows use protected write capacity under
  storage pressure. Routine agent sample stdout is excluded from systemd
  journald and OpenRC operational logs; the service pipeline now consumes the
  sample stream through local durable ingestion, while stderr remains
  diagnostic output.
- Integer memory/root-disk capacity counters are aggregated as gauges, while
  raw decimal values retain full precision. Agent server identity is persisted
  at `/var/lib/payesh/server-id` by the service templates, and omitted IDs no
  longer fall back to a shared literal. Logical bridge/bond/VLAN/tunnel
  interfaces are excluded from the billing baseline using naming and Linux
  device metadata.
- Retention deletes the exact selected row IDs before recording gaps. Raw metric
  gap pages have an independent `gaps_cursor`, and malformed/empty metric JSON
  columns decode independently. Store-level log insertion re-runs redaction.
  CLI receipt time is captured after the input envelope is read.
- The local server runs bounded retention/prune work at startup and every five
  minutes. Rollup read failures are reported as retryable `503` responses
  rather than returning stale summaries. Raw coverage includes validity-only
  unavailable metrics and explicitly lowers confidence when a gap is present.
- Billing totals accept an explicit authoritative interface selection through
  the agent/collector flags; the safe discovery heuristic remains the default.
- `payesh capture-log` registers and persists bounded file snapshots, and
  historical log queries support bounded severity and text-search filters.
- Historical file/journal-log API/CLI queries refresh registered sources on demand;
  persisted pages enforce the one-MiB response budget and continue with an
  opaque cursor. Service bootstrap preserves existing server metadata and
  successful ingestion updates only heartbeat/freshness state.
- Storage pressure starts bounded history eviction before the hard ceiling,
  checkpoints WAL, and incrementally vacuums reusable pages. Protected server
  identity and traffic-period rows are not eviction targets; raw samples remain
  durable when only derived rollup writes are paused.
- File cursors include a bounded content fingerprint so same-inode copytruncate
  or rewrite is detected while ordinary appends remain resumable.
- Retention eviction now records only contiguous sequence runs, so an expired
  sample cannot falsely claim that an intervening retained sequence is missing.
  One-sided gap timestamps remain unknown and ranged queries conservatively keep
  those gaps visible instead of assigning them a fabricated instant.
- The local server derives stale/disconnected state from heartbeat age. The
  follow-mode ingest process sends a separate 15-second heartbeat cadence, so
  economy metric sampling does not extend freshness indefinitely. Managed
  storage accounting includes configured Payesh operational-log directories.
- Historical file queries resume at the source cursor (resetting safely after
  rotation), and registered journald units support bounded live tails through
  `--after-cursor`. Metric pages stop before the response byte ceiling and
  return a continuation cursor.
- The local API is loopback-by-default in `payesh-server`; `/healthz` is the
  only unauthenticated route. Protected local routes require a configured
  bearer token and expose bounded server, metric, log-source, log-history, and
  live-tail reads. Fleet/session/auth routes remain owned by package 04.
- The CLI supports collection, server registration, bounded ingestion, raw or
  rollup metric queries, traffic-period queries, bounded log reads/history,
  bounded log capture, pruning, and storage usage. The installed agent service
  registers its persisted identity and pipes samples into the local SQLite
  store.

## Interfaces consumed or changed

- `contracts.NodeMetricSample` is the node wire shape; `MetricSample` is the
  hub-stamped durable shape.
- `monitoring.Store.IngestNodeBatch` accepts `(serverID, samples, gaps,
  receivedAt)` and is the integration point for package 04 transport.
- `monitoring.Store.QueryMetrics`/`QueryMetricsWithGapCursor`, `QueryRollups`, `QueryTrafficPeriods`,
  `QueryLogs`, and the protected `monitoring.API` provide bounded read paths for
  package 02 and later fleet/alert consumers.
- `monitoring.BuildRollupsWithGaps` carries reset/gap uncertainty into rollups.
- `monitoring.TailConfiguredLog` and `monitoring.TailJournal` are bounded local
  tail primitives; authenticated node transport remains a later-package
  adapter.

All commands passed on the development host. The CLI was also smoke-tested by
registering a temporary server, piping a real collector JSON sample into the
SQLite ingest command, and querying it back. The resulting Linux matrix binary
sizes were approximately 11 MiB for the agent, 14 MiB for the server, 11 MiB
for the CLI, and 2.3 MiB for the privileged stub.

On 2026-09-11, a fresh Linux amd64 build was exercised on the authorized Ubuntu
20.04 server (kernel 5.4.0-29, systemd). The real `/proc`, `/sys`, and
`/proc/net/dev` collector emitted memory, disk, load, uptime, and interface
counters; persisted installation identity stayed stable while each agent
restart received a fresh collector epoch; and first-sample CPU values remained
explicitly unavailable. Two samples were durably ingested into SQLite and
queried back with network coverage. The follow-mode service pipeline
(`payesh-agent -interval=5s | payesh ingest -follow`) produced three durable
acknowledgements. The same run verified bounded file-log capture, credential
redaction, continuation grouping, database-backed server registration, health,
and bearer-token enforcement (unauthenticated request 401, authenticated list
success). All binaries, databases, logs, and listeners were removed afterward.

## Measured costs and limitations

The core real-Linux collector, SQLite ingest/query, log-capture, and local API
paths are now verified on Ubuntu 20.04. Remaining environment-dependent work is
systemd-managed startup/restart, OpenRC startup, journald behavior, rotation
under load, and disk-full/WAL pressure. Node offline spool, TLS transport, enrollment,
  and fleet authentication remain package 04 responsibilities. Calendar-month
  derivation and alert/incident orchestration remain package 05
  responsibilities.

## Next-package inputs

Package 04 should use `IngestNodeBatch` only after durable acceptance, preserve
the returned idempotency result, and feed explicit `CoverageGap` records for
spool eviction/reconnect loss. It should not add a second SQLite schema or
invent a competing receipt timestamp. It must supply authenticated server
records before ingest and use the service definitions as install templates.
